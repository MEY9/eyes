### ⚠️ 关键坑 2：本机 git push 走全局代理会 TLS 握手失败
- 全局 `~/.gitconfig` 里 `http.proxy`/`https.proxy = http://127.0.0.1:17890`（Clash Verge）。

  即：清空代理环境变量 + 用 `-c` 把 git 的 proxy 覆盖为空。已验证推送成功。

## Git 推送配方（本仓库，17:14 实测定版）

⚠️ 上午可用的「清掉代理直连」法在 17:14 已失效：TCP 直连 github.com:443 直接 21s 超时（只有 TUN 能出网）。
✅ **当前可靠配方**：
```
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy \
  git -c http.proxy=http://127.0.0.1:17890 -c https.proxy=http://127.0.0.1:17890 \
      -c http.sslBackend=schannel push origin main
```
三个要点：
1. Bash 环境自带 `http_proxy/https_proxy=127.0.0.1:28102`（WorkBuddy sandbox 代理），对 GitHub 返回 **502 Bad Gateway**，必须 unset，否则 git 优先用它。
2. 直连不通，必须走 Clash Verge 的 17890。
3. `http.sslBackend=schannel` 才成功；`openssl` 后端报 `unexpected eof while reading`。
排查手法：`Invoke-WebRequest -Uri https://github.com -Proxy http://127.0.0.1:17890 -Method Head`（PowerShell/.NET 走 TUN，能正常 200）——用它先验代理是否通，再让 git 用同一个代理。
