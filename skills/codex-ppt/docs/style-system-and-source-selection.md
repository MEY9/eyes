# Style System And Source Selection

本文件约束教学课件视觉稿的主风格建立和素材生产，不改变 Agent A 的教学设计流程，也不改变 `image-to-editable-ppt` 的对象重建流程。

## 核心原则

课件不是先逐页生图、再从页面中猜风格，而是先建立一套可复用的主风格系统，再把教材内容转译成底图、人物、场景、道具、图示和页面构图。

主风格保持稳定，页面构图根据教学功能变化。不能把一张样张当作固定模板，也不能让每页自由发挥到失去教材感。

## 主风格系统

每次正式生成前，必须形成一个可复用的 style brief，至少包括：

- 时代与媒介感：例如 80、90 年代教材插画、彩色铅笔、水彩、版画或印刷质感；
- 色彩系统：主色、辅助色、强调色、中性色、明度和投影可读性规则；
- 线稿与质感：线条粗细、边缘软硬、纸张颗粒、套色偏差、阴影和高光；
- 人物系统：年龄比例、脸部特征、服装、动作、表情、群像关系和视角；
- 场景系统：校园、家庭、社区、自然环境和室内空间的共同绘制规则；
- 图示系统：箭头、流程、卡片、标签、对比框、时间线和关系图的视觉语言；
- 字体系统：普通、清晰、可投影的中文字体，禁止艺术字、书法体、毛笔体、装饰体和变形字；
- 构图系统：封面、导入、讲授、提问、活动、练习、反馈、总结和作业页的页面角色；
- 资产规则：哪些内容应单独生成，哪些内容只能作为背景，哪些内容必须保留为严格输入；
- 禁止项：与教材内容无关的装饰、品牌标识、错误文字、时代错置、过度复杂的背景和重复构图。

固定的是视觉身份，变化的是页面任务。风格包不能规定所有页面使用同一种三卡片、左右分栏或人物站位。

## GitHub 风格来源筛选

当用户要求从 GitHub 寻找主风格或优秀项目时，先记录候选项目，再决定是否纳入风格系统。这里的目标是寻找已经实践过的视觉语言、构图方式、素材组织和生成方法，不做许可证审查，也不把项目原样搬进课件。每个候选至少记录：

```json
{
  "repository": "owner/name",
  "url": "https://github.com/owner/name",
  "checked_at": "YYYY-MM-DD",
  "evidence": ["README", "sample gallery", "source assets", "working demo"],
  "reusable_parts": ["palette", "texture", "composition", "asset pipeline", "prompt structure"],
  "adaptation_notes": ["what to borrow", "what to change", "how to fit the textbook content"],
  "fit_for_education": "high|medium|low",
  "decision": "adopt|adapt|reference-only|reject",
  "reason": "..."
}
```

优先选择有实际案例、可运行示例、可复用资产或生成流程、并能解释其视觉规则的项目。星标数量只作为发现线索，最终以视觉质量、实践效果和教育场景适配性为准。不同项目的色彩、笔触、构图、素材组织和提示词方法可以自由组合，形成新的课件主风格。

## 资产生产顺序

风格确认后，先建立轻量资产计划，再生成页面：

1. 生成风格样张：验证线稿、色彩、纸张质感、人物和文字可读性。
2. 生成底图方向：确定校园、家庭、社区、实验或自然场景的共同空间语言。
3. 生成可复用素材：人物角色、动作、道具、图标、边框、纹理和关系图组件。
4. 建立页面资产映射：明确哪些资产属于哪一页、扮演什么教学角色、是否为严格输入。
5. 根据教学功能选择构图：同一主风格下，导入页、讲授页、活动页、练习页和总结页使用不同构图。
6. 生成代表性样张组：至少覆盖封面/导入、普通讲授、活动/练习/反馈三类页面。
7. 样张通过后再批量生成完整视觉稿。

资产计划必须服务教学目标。不能为了“看起来丰富”批量生成没有教学作用的人物、装饰或背景。

## 风格来源与生成记录

`deck_spec.json` 必须保存：

- `style_source_records`：GitHub 或其他参考来源，以及从中提炼的视觉规则；
- `style_brief`：本次课件实际采用的完整风格规则；
- `style_lock`：正式批量生图时必须遵守的最小视觉约束，字段定义见 `docs/style-lock-and-review.md`；
- `asset_plan`：底图、人物、场景、道具和图示资产的用途；
- `thumbnail_board`：多页课件的缩略图板路径、审核状态和节奏审核记录；
- `style_lock_status`：样张审批前为 `draft`，用户批准后为 `locked`；
- `approved_style_references`：已批准的样张及其页面角色。

样张批准后，后续页面只能沿用已锁定的视觉系统。若发现主风格本身有问题，应先修改 style brief 并重新生成受影响的样张，不能在单页提示词中悄悄改变风格。

## 完整课件确认与风格入库

样张通过只锁定本次课件的批量生产规则。它不是系统风格入库门槛。完整 PPT 生成后，必须先完成视觉稿、对象级可编辑 PPTX、动画和视频（如有）的最终 QA，并等待用户确认完整课件没有问题。

用户确认后，才把本次 PPT 的视觉系统提炼为可复用风格包：

- 项目内保存一份 `style/` 快照，便于回溯本课件当时的 Style Lock、样张、页面角色和 GitHub 来源；
- 系统级保存一份不含课题正文和私人内容的 style record，位置为 `${CODEX_PPT_HOME:-~/.codex-ppt-skill}/references/{style_name}.md`；
- `deck_spec.json` 写入 `style_library_record`，记录风格 ID、版本、项目快照、系统文件、来源和用户最终确认依据；
- 同名风格不得静默覆盖，必须建立新版本或明确复用已有版本；
- 之后的新 PPT 先加载风格系统，再按新教学大纲重新选择页面构图，不能把上一份课件的页面内容和版式整体复制。

单张样张、缩略图板和未完成课件只能作为项目临时参考，不能自动写入系统风格库。
