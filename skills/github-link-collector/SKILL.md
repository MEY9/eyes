# GitHub 链接收藏 Skill

## 目标

把与本项目有关的 GitHub 项目保存到仓库中的 `references/github-projects.md`，让以后换电脑或忘记项目时，可以通过文档找回项目、用途和研究价值。

## 触发边界

只有用户明确提出“帮我存储 GitHub 链接”或含义完全相同的指令时才使用本 Skill。用户只是让你搜索、介绍、比较或分析 GitHub 项目时，不要自动修改收藏文档。

## 工作流程

### 1. 识别项目

- 从用户消息中提取 GitHub 仓库 URL；如果只有项目名称，先要求用户提供链接或明确允许搜索。
- 判断项目是否与教育课件、教育可视化、PPT 产品、HTML 课件、交互演示、2.5D/3D 视觉资产或 AI 辅助创作有关。
- 对每个项目记录真实可核验的功能，不把项目名称或 README 标题当成功能结论。

### 2. 形成待审核记录

把记录添加到 `references/github-projects.md` 的“待审核项目”部分，至少包含：

- 项目名称与 GitHub 链接
- 状态：`待审核`
- 主要功能
- 对本项目的用途
- 适用产品类型
- 技术栈或关键技术（无法确认时写“待确认”）
- 是否值得深入研究
- 备注，包括维护状态、许可证或明显限制（能确认时才填写）

不要擅自把新项目标记为“已收录”，也不要把推测写成事实。

### 3. 等待审核

完成文档修改后，向用户展示新增项目和判断依据，明确说明项目仍为“待审核”。在用户没有明确审核通过前，不移动到正式项目列表，不提交 Git，不推送远程仓库。

### 4. 审核通过后的同步

只有用户明确表示审核通过并要求同步时，才执行：

1. 将项目从“待审核项目”移动到“项目列表”。
2. 将状态改为 `已收录`。
3. 检查 `git diff`，确认只包含本次收藏相关修改。
4. 提交清晰的中文 commit，例如 `收录 GitHub 项目：项目名`。
5. 使用仓库已有的 `origin` 推送当前分支；推送失败时报告原因，不修改认证配置或索要用户 Token。

如果用户只批准其中一部分，只处理被批准的项目。

## 文档位置

默认目标文件：`references/github-projects.md`。遵守该文件已有的分类、字段和审核约定，不重复创建第二个收藏文档。

## 安全与权限

- GitHub 链接和项目说明可以写入仓库；不要把访问令牌、私钥、Cookie 或本机凭据写入文档。
- 不下载或复制项目源码，不执行陌生仓库脚本；除非用户另行要求研究该项目。
- 不因“收藏”而自动安装依赖、创建账号、修改 GitHub 设置或改变远程地址。
- 推送远程仓库是外部写入操作，必须以用户明确的审核通过和同步要求为前提。
