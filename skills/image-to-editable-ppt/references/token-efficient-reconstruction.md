# Token-Efficient Page Reconstruction（省配额执行策略）

> 定位：**效率策略，不是质量策略**。本文件只约束“怎么少花 token”，不放宽任何质量要求。
> 质量红线（完全分解不变量、对象来源规则、validation 门禁、逐字核对）全部保持强制，本文件不得被引用为降低验收标准的依据。
> 当本文件与任何质量规则冲突时，质量规则无条件优先；只有“重复读、反复看、无效重做”是本文件要消除的对象。

## 1. 为什么要省

Page worker 的 token 消耗大头不是生图（图像后端走 CLI，不占模型配额），而是：
- 通读长篇参考文件；
- 反复全页读图做自检；
- 中断后不核验已有产物就从头重做；
- 缺少经验导致的返工循环。

实测同一类页面：无策略 8.8M–19.2M tokens/页，采用本策略后 2.4M–7.1M tokens/页，validation 结果同样为零警告零违规。

## 2. 允许的节省手段（白名单）

### 2.1 参考文件按需跳读
- 只读合同（worker-prompt.md）明确指向的章节；禁止为“保险”而通读全部参考文件。
- 合同已点名的章节也允许先读该章节的决策规则部分，字段级细节在真正要写 manifest/validation 时再查。
- 已在本次执行中读过的内容不重读。

### 2.2 自检读图定点化
- 构建前完整看一次源图（这一步不可省——清单是红线的起点）。
- 自检阶段按“文本区、前景资产区、背景区”三个关键区域定点对比，不反复读全页图。
- 同一区域在一次自检里看清楚并记录结论；禁止“再看一眼”式的重复读图。预览对比优先用 `editppt page contact-sheet` 的拼图，一次读图覆盖多张。

### 2.3 产物核验复用（Recovery）
- 页面目录已有前次执行的部分产物时，先按合同 Recovery 规则核验（对照 source 与 backend 合同、哈希与视觉内容），合规的直接复用，在 `imagegen-jobs.json` 如实记录来源；不合规才重建。
- 复用省下的是图像后端调用与重做时间；核验本身的读图属于必要成本，不省。

### 2.4 已验证经验前置
- Parent 派发时，把本 run 内已验证的修复经验写进 worker 提示词（例如：fitter 钳制用 `line_height: 1.0`、构建器不写 lnSpc 时多行文本盒逐行落位、字体用 Microsoft YaHei Bold 并记录替代、透明 sheet 先清 <400px alpha 噪点、OCR 漏检文字按墨迹实测并标 `font_size_source: measured`、提问框优先原生形状）。
- 经验只描述“怎么做能一次做对”，不降低任何验收标准。

### 2.5 迭代收敛预算
- Parent 可在提示词中给出单页 token 预算目标（参考值：常规页 ~3M，复杂页 ~7M）。预算是规划目标，不是验收条件；worker 发现为守住预算需要牺牲必要的修复时，必须放弃预算约束并如实完成修复。

## 3. 明确禁止的“节省”（红线，违反即失败）

以下任何一条都**不可以**为了省 token 而省略，出现即视为未完成页面合同：

1. **构建前的完整页面清单**：省略清单直接改对象，或缩小清单范围（小、淡、背景、装饰元素一个都不能漏）。
2. **完全分解不变量**：整页栅格作背景、“整页图+文字覆盖”永远不可接受；前景素材必须经图像编辑分离，禁止源图裁剪或近似替代；每层资产的来源与不可编辑范围必须记录。
3. **课文/正文文字逐字核对**：所有可读文字必须与源逐字一致并重建为原生文本框；省掉逐字核对直接提交，validation 阶段发现即返工，比当场核对更贵。
4. **validation.json 的完整自检与修复循环**：`passed: true` 前发现的问题必须修复；不能把“预算用完了”作为带病提交的理由。
5. **必要的返工**：发现真实缺陷必须修；预算目标让位于质量，见 2.5。
6. **产物诚实记录**：复用的资产、后端 fallback、字体替代必须如实记录；省略记录不可接受。

## 4. Parent（编排方）职责

- 派发时在 worker 提示词中：点名要读的参考章节、给关键区域自检指引、列出已验证经验、声明 token 预算目标（可选）、注明可复用的既有产物。
- 发现 worker 单页消耗异常（如 >10M）时，检查是否在重复读文档或全页读图，并在补发提示词中收紧对应条目。
- 不得以“预算”为由接受 `passed: false` 的页面，也不得暗示 worker 跳过红线项。
