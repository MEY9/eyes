# PPT 动画视频

## 定位

本技能是 Agent B 的后处理技能。输入是已经完成对象级重建、动画分组和动画 QA 的可编辑 PPTX；输出是用于展示或发布的竖版 MP4。它不负责教学设计、课件大纲、视觉稿生成或 PPTX 对象重建。

## SQLite Catalog 协同

调用时沿用 Agent B 传入的 `deck_id`、`style_id@version` 和 `catalog_db`，为 PPTX 动画结构 QA 建立 `animation_qa` run，为视频生成建立 `video` run。读取 catalog 中已通过的 `editable_rebuild` artifact，不根据文件名新建课件身份。

- 在动画结构 QA、字体修复、音乐资源和 MP4 输出完成后，分别登记 artifact、哈希和验证证据。
- 只有视频和动画 QA 结果完整，才把对应 run 标记为 `passed`；失败时保留日志并返回 Agent B。
- 本技能不修改 Style Lock、风格版本或用户最终审批状态，也不触发风格入库。
- API key、音乐下载凭据和其他秘密不得写入 SQLite 或项目快照。

固定链路：

Agent A 教学设计
→ Agent B 课件大纲
→ codex-ppt 视觉稿
→ image-to-editable-ppt 对象级重建
→ PPTX 动画语义分组与后处理
→ 本技能生成动画视频

本技能生成的是“按动画状态渲染的展示视频”，不是把每页静态图硬切成视频，也不是把整页图片作为唯一动画对象。PPTX 本身的原生动画仍必须保留在 PPTX 中；视频使用同一份可编辑对象和动画清单，按语义组逐步显现。

## 输入门禁

调用前必须存在并通过检查：

- 最终可编辑 PPTX；
- 动画清单，例如 `working/animation_manifest_logic.json`；
- 每页的对象级动画分组、效果、触发顺序和教学目的；
- 视觉稿或 `origin_image/` 仅用于参考和封面缩略图，不作为缺字体时的替代渲染方案；
- 项目课题、总页数、视频比例和输出目录已经确定。
- `rights_manifest.md` 或等价的资源记录，能够说明字体、音乐和视频资源的使用范围。

若没有语义动画清单、PPTX 仍是整页图片，或可编辑 PPTX 未通过 image-to-editable-ppt 验收，退回 Agent B，不在本技能中补做对象重建。

## 完整流程

### 1. 锁定输出规格

默认使用 3:4 竖版 1080×1440、30 fps。用户或项目明确要求 9:16 时使用 1080×1920；不得擅自改变比例。

视频完整播放全部课件：封面展示时间加上所有页面的初始状态和动画组状态。取消一分钟上限，不压缩或跳过后半部分页面。

封面必须作为最终 MP4 的第一个视频片段拼接在视频时间轴最前面：视频第 0 秒的首帧必须就是封面，封面之后才进入第一张正式页。不能只把封面作为播放器封面图、缩略图或单独文件交付；合成后必须用媒体检查确认封面片段确实存在于视频流中。

建议输出命名为：

`outputs/<课题>_课件动画_<比例>.mp4`

视频画面中不得增加任何说明性叠字，例如“预览”“正式课堂”“逻辑动画版”“小红书竖屏预览”“点击组按课堂逻辑组合播放”等。只保留课件本身的标题、正文、页码、进度条和用户明确要求的封面元素。

### 2. 准备中文字体和渲染环境

先从 PPTX 的主题、文本框和项目资源中识别实际字体。若渲染器缺字：

1. 安装可合法使用的中文字体到当前用户字体目录或项目字体目录；
2. 建立字体配置并让无界面 PPT 渲染器加载该配置；
3. 用一个包含中文标题、正文和小字号文字的状态页测试；
4. 只有确认中文实际显示后，才开始全量渲染。

禁止因为缺字体而擅自改用原始整页图片、整页底图或删掉文字。字体安装和配置是渲染修复，不得修改最终可编辑 PPTX 的教学内容和对象结构。每个项目应记录字体来源、配置路径和测试结果。

### 3. 按语义动画组渲染状态

读取动画清单，逐页生成：

- 初始状态：仅显示静态背景和不参与动画的对象；
- 每个动画组状态：在上一状态基础上显示当前逻辑组；
- 需要短过渡时，在视频合成阶段完成淡入、擦除或聚焦，不改变动画组的语义顺序。

动画状态必须以可编辑 PPTX 对象为来源。背景、纸张肌理、固定边框和不会改变讲解顺序的装饰保持静止。标题、解释文字、对应插图、箭头、曲线、证据卡片等属于同一教学动作时，应作为一个组同步或近邻显现，不能每个对象单独产生一个点击。

效果沿用 Agent B 的动画清单：

- `fade`：导入、标题、总结和需要平稳进入的内容；
- `wipe`：流程、阅读路径、时间顺序、情感曲线和因果方向；
- `circle(in)` 或同等聚焦：关键证据、转折和结论；
- `appear`：答案、关键词和板书式确认。

视频不应只使用一种效果，也不使用无教学目的的旋转、弹跳、随机飞入或持续循环。动画效果必须和 PPTX 中的动画清单一致。

### 4. 组织竖版视频画面

每个演示页面放入竖版画布中，保持课件比例和文字可读性。页面内容作为中央演示卡片，周围留出稳定安全区。

正式页面必须包含：

- 右上角当前页码，格式如 `02 / 19`；
- 进度条放在演示动画卡片的正下方，位于下方留白区域的顶部，不贴视频最底部；
- 进度条长度反映整段视频进度，随页面和动画组推进；
- 不添加标题、脚注、说明标签或产品宣传语。

封面按用户确认的封面构图保留；若封面有缩略图，缩略图应来自已确认的页面状态并确保文字清晰。封面不得出现技能名、制作说明或平台说明，也不得出现“置顶”字样、置顶标签或类似角标；如源图或模板中已有该内容，必须在封面进入视频前移除。

### 5. 添加背景音乐

背景音乐优先使用用户提供或本机已有的许嵩、汪苏泷、周杰伦音乐。三位歌手是本流程的音乐偏好，不要求自动搜索或下载某一首指定歌曲；如果项目中有多首，按课堂气质、旋律干扰度和完整视频时长选择最合适的一首。歌词较多的歌曲也可以使用，但必须明显降低音量，不能盖过课件文字和讲解。

本流程面向用户指定的非商业课件演示，不因缺少商业授权字段而自动阻断制作；仍需记录音频来自用户提供、本机已有或项目资源的事实。不得主动抓取、破解或下载来源不明的音频，也不得把音乐凭据写入 SQLite、日志或 Git。若指定歌手的音频不存在，使用项目已有的合适背景音乐并在 QA 中记录，不伪造歌曲来源。

将音乐循环或裁剪到完整视频时长：

- 初始音乐增益默认降低约 18～24 dB，最终以听感和响度检查为准；
- 无旁白页面保持约 10%～15% 的存在感；有旁白、重点文字或互动反馈时自动压低约 4～8 dB；
- 音乐峰值建议不超过 -3 dBFS，避免削波、刺耳和手机外放失真；
- 开头使用约 0.8 秒淡入，结尾使用约 1.2 秒淡出；切页或重要结论处避免突然换歌或强节拍撞击；
- 音乐是背景，不把音乐做成视频主角；
- 输出必须同时包含视频流和音频流。

在 `resources/` 保存实际使用的音频文件，并在音乐记录中写明歌手、曲名（如已知）、来源类别、文件名、增益、淡入淡出和是否发生 ducking。用户未提供音频时，不为了满足歌手偏好而擅自联网下载。

### 6. 合成和验收

至少检查以下内容：

1. 抽检封面、第一张正式页、中段页、含大量中文页和最后一页；
2. 检查视频第 0 秒首帧为封面，并确认封面片段已实际拼接在第一张正式页之前，而不是仅作为播放器封面图或缩略图；
3. 检查封面画面没有“置顶”字样、置顶标签或类似角标；
4. 确认中文字没有空框、乱码、丢失或被裁切；
5. 确认页面内对象确实按教学组逐步出现，不是单纯页面切换；
6. 确认每个正式页右上角页码正确；
7. 确认进度条位于演示卡片下方，而不是视频底边；
8. 搜查并人工复核视频画面中是否出现禁止的说明性叠字；
9. 确认没有超过一分钟的硬限制，视频覆盖完整课件；
10. 用 FFmpeg 或等效工具验证 MP4 可解码、时长、分辨率、帧率和音视频流；
11. 没有 PowerPoint 播放引擎时，明确记录“视频按动画状态渲染，未完成桌面 PowerPoint 实时播放验证”，不得声称已经完成桌面播放验证。

## 固定项目产物

建议保存在当前课件项目目录：

```text
working/animation_manifest_logic.json
working/render_animation_states.py
working/make_xiaohongshu_video.swift
working/patch_render_fonts.py                 # 仅在需要时
working/video_qa.md
resources/<背景音乐文件>
resources/<背景音乐来源与处理说明>
outputs/<课题>_课件动画_<比例>.mp4
```

脚本可以按本机环境改写，但必须保留以下不变量：使用可编辑 PPTX 状态、语义组顺序、完整时长、中文字体保真、页码、演示卡片下方进度条、适当控制音量的背景音乐和最终验证。

## Agent B 调用规则

Agent B 在动画 PPTX 后处理和结构 QA 通过后调用本技能。调用参数至少传入：

- 可编辑 PPTX 路径；
- 动画清单路径；
- 课题名和总页数；
- 输出比例；
- 当前项目的资源、字体和输出目录。
- `deck_id`、`style_id@version`、`catalog_db` 和 animation/video 的 `run_id`。

Agent B 接收本技能的输出后，必须把视频路径、视频规格、音乐来源、字体修复记录和验证结果写入最终交付记录。视频生成失败时，不得把静态幻灯片或无文字版本当作成功结果；应保留错误日志并返修字体、渲染或合成步骤。

同时把可编辑 PPTX、动画清单、字体修复记录、音乐来源与处理记录、MP4 和 `video_qa.md` 登记到共享 catalog，并把 `deck_id`、两个 run_id 和 artifact 列表返回给 Agent B。完整课件用户确认后，风格入库仍由 Agent B 执行。

视频阶段结束后，如果用户要发布到多个平台，交给 `ppt-social-publishing` 继续处理。该技能读取本技能生成的 3:4 和 9:16 母版，只做平台目录分发、微信公众号固定排版、文案和标签，不在视频阶段混入平台文案或公众号 HTML。
